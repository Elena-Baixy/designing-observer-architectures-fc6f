# 2404.19737 — Better & Faster Large Language Models via Multi-token Prediction (Gloeckle, Youbi Idrissi, Rozière, Lopez-Paz, Synnaeve; FAIR/Meta, 2024)

## Research question
Does training LLMs to predict the next n tokens at once (an auxiliary multi-token loss) improve sample efficiency, generative/reasoning ability and inference speed compared with next-token prediction?

## Method / architecture
- Loss: L_n = -sum_t log P(x_{t+n:t+1} | x_{t:1}), factorized through a shared latent z_{t:1}:
  L_n = -sum_t sum_{i=1..n} log P(x_{t+i} | z_{t:1}).
- Architecture: shared transformer trunk f_s, then n independent heads f_{h_i} (one transformer layer each), then a shared unembedding f_u. P(x_{t+i}|x_{t:1}) = softmax(f_u(f_{h_i}(f_s(x_{t:1})))).
- Compute matching: adding n-1 head layers removes n-1 trunk layers.
- Memory-efficient training: forward/backward each head sequentially, accumulating gradients at the detached trunk output (d = z.detach(); per-head loss.backward(); z.backward(d.grad)). Peak memory drops from O(nV + d) to O(V + d).
- Inference: use only the next-token head, or use the extra heads for self-speculative (blockwise parallel / Medusa-style) decoding.
- Alternatives (App. B, Table S4): replicated unembeddings, **linear heads** (= linear probing of z), causal heads (head i stacked on heads 1..i-1), anticausal heads (predict the farthest token first, then refine). None significantly beat the parallel design.
- Theory (Sec. 5):
  - 2-token prediction doubles the weight on I(X;Y): H(X)+H(Y) = H(X|Y) + 2I(X;Y) + H(Y|X).
  - n-token loss gives implicit weight n(n+1)/2 to "choice points" vs. n to inconsequential tokens.

## Models
- Code: 0.3B to 13B, trained from scratch on >= 91B code tokens.
- 7B models on 200B / 1T code tokens.
- 7B byte-level model on 314B bytes.
- 7B natural-language models on 200B and 500B tokens.
- Small 1M–1B models (induction); 30M/100M models (polynomial arithmetic).
- No public weights/code link in the main text.

## Datasets
- Evaluation: MBPP, HumanEval, APPS/Intro, CodeContests (fine-tuning), GSM8K (8-shot).
- Summarization (8 benchmarks, ROUGE-L), e.g. CNN/DM, XSum, Multi-News, SAMSum.
- Six standard NLP multiple-choice benchmarks.
- Synthetic: children's stories with 2-token names (induction); polynomial arithmetic in F7[X]/(X^5).

## Probe design
Not a probing paper. The "linear heads" variant amounts to linear probes of trunk z for x_{t+i} (App. B).

## Metrics
pass@k (Chen et al. estimator; oracle temperature), ROUGE-L F1, accuracy, decoding speedup / tokens per forward.

## Key numbers
- Benefit grows with scale. MBPP pass@1 change vs. baseline is -1.7 at 0.3B and +4.5 at 13B. The 13B model solves 12% more HumanEval and 17% more MBPP problems.
- **Horizon ablation** (7B, 200B code tokens; MBPP@1 / HumanEval@1):
  - n=1: 30.0 / 22.8. n=2: 30.3 / 22.2. **n=4: 33.8 / 24.0**. n=6: 31.9 / 20.6. n=8: 30.7 / 20.0.
  - The optimum is around n=4; gains shrink past it. APPS favors n=6.
- Bytes: n=8 beats n=1 (MBPP@1 32.3 vs. 19.3); n=16 gives 28.6 and n=32 gives 23.0. Benefit falls off at longer horizons.
- 1T tokens (4 epochs), n=4 vs. n=1: MBPP@1 43.1 vs. 40.7.
- Self-speculative decoding: 3.0x speedup on code (2.5 of 3 suggestions accepted), 2.7x on text, 6.4x for 8-byte models.
- Natural language: n=2 is on par with baseline on multiple-choice benchmarks; n=4 regresses slightly. Summarization ROUGE-L improves (e.g. ~26.2 to ~26.7 at 200B tokens).
- Induction: 2-token loss greatly helps models of 30M parameters and below; the advantage disappears at >= 100M.

## Limitations
- Horizons are short (2–8 tokens; up to 32 bytes).
- No gains on multiple-choice NLP tasks at 7B; benefits appear only at scale.
- n must be tuned per data distribution.
- Future work they suggest: auxiliary losses "in embedding spaces" (LeCun 2022) rather than token space.

## Relevance to observer/forecasting hypothesis
- **Template for multi-horizon heads.** Shared trunk (the observer's trajectory memory), then per-horizon heads, then per-horizon losses summed. For the observer, swap token heads for heads predicting **latent summaries of future windows** at scales such as {16, 64, 256, 1024, 2048}, and train them in parallel with the sequential-backward memory trick.
- **Evidence that token-level targets degrade with horizon.** Token-space targets peak around 4 tokens (8 bytes) and lose value beyond that. This motivates **compact latent or attribute targets** for 100–2048-token horizons, which is the authors' own suggested direction.
- **Choice of head design.** Causal or anticausal stacked heads are an option for coarse-to-fine multi-scale prediction (anticausal = predict the far summary first, then refine nearer windows). In this paper they gave no clear gain over parallel heads.
- **Choice-point weighting.** Multi-step losses up-weight tokens whose consequences persist, which is exactly where unsafe turns or topic commitments happen. This supports multi-horizon auxiliary targets for improving hazard prediction.
- **Linear heads as the baseline.** The linear-head variant is the "direct probe" baseline.
- No survival or CPC loss here.

# LatentQA (Pan, Chen, Steinhardt; arXiv 2412.08686, ICLR 2026) — DEEP READ (all 34 pages)

**Question.** Can we train a decoder LLM to answer open-ended natural-language questions about a target LLM's activations (LatentQA), and use it for reading + steering?

**Task framing (important for us).** Explicitly "predict qualitative properties of the model's *future* completion given activations from the *current* prompt" — i.e. LatentQA is already a *forecasting* verbalizer, but horizon = "the next reply" with no notion of when (timing) and labels describe the whole completion (persona/goal/style).

**Data (16,732 LatentQA points; in repo `code/latentqa/data/`).** Built by o1-preview: seed controls in 3 categories (4,670 goals, 3,359 personas, 8,703 extractive-QA) → expanded into (control_user, control_model, stimulus_user, stimulus_model) dialogs → 5 description QA + 5 reasoning QA per dialog. Three data types: (1) control acts; (2) stimulus acts with control *masked*; (3) stimulus+completion acts with control masked. Files: train/control.json (16,732), stimulus.json / stimulus_completion.json / system.json (7,844), qa.json (dict, 16,784 keys of QA lists). Eval set = 500 controls.
Design decisions: activation masking (prevent reading control tokens directly), data augmentation over 3 types, faithful completions (generated by o1 rather than target).

**Architecture (LIT = Latent Interpretation Tuning).** Decoder = copy of target LLM + LoRA (r=32, α=64, attn+MLP; repo default r=16, α=32 incl. lm_head). Read layer k=15 residual stream of target (Llama-3-8B-Instruct, 32 layers), write at decoder layer ℓ=0 (input embeddings) by substituting the activations of dummy "???" placeholder tokens (one per read position; ~50 tokens × 4096). Sweep table (eval ppl): k=15,ℓ=0 best (1.013); writing deeper is worse. lr 1e-4, batch 128, 4×A100. Reading: greedy decoding on "[Act] + question", 1×A100.
Code: `lit/utils/activation_utils.py` (forward hooks to cache outputs of layer modules; `generate_substitute_layer_single` substitutes activations by mask at write layer), `lit/utils/dataset_utils.py` (chat-template magic numbers for Llama-3/3.1-8B, Llama-3-70B, Ministral-8B, Mistral-Small-24B, R1-Distill-Llama-8B/Qwen-32B, gemma-3-4b-it, Qwen3-4B-Instruct-2507), `lit/train.py` (DDP/FSDP torchrun), `lit/reading.py`, `lit/control.py`. Released decoder: HF `aypan17/latentqa_llama-3-8b-instruct`.

**Control.** STEER([Act], QA) = gradient of decoder CE loss of answer wrt Act; backprop into LoRA (r=8) on target layers 0..k; per-layer loss over layers 0..k works better.

**Results.**
- Hidden system prompt (persona) from *user-turn* activations only: easy 100% / hard 92% vs GPT-4 prompting given full dialog (97.3/73.3) and SelfIE (~23/16). Gemma-3-4b: 90/80 vs prompting 76/76.
- Relational extraction (Patchscopes setup, 6 tasks): LIT avg ≫ linear probe (+32.2) and Patchscope (+38.2), e.g., Country_Curr 86.9 vs 17.7 / 24.3.
- Debiasing CrowS-Pairs: LIT only statistically significant method (mean LL diff 3.70 vs 4.05 no-control; % stereotype 60.9 vs 64.3).
- Steering to Golden-Gate / unseen personas; eliciting harmful knowledge: 100% harmful (harmful prompts), 87% (benign prompts) vs 0 prompting.
- Scaling: test loss drops with model size (1B→70B) and data (1/4→1). Hidden-persona accuracy 1B 30/12, 3B 96/88, 8B 100/92.

**Limitations.** Narrow data (3 control types); hallucination risk, no ground truth for latents; no temporal (when) information; single read layer; reads a static window of activations (prompt), no trajectory memory.

**Relevance to observer hypothesis.**
- LatentQA/LIT is the canonical "direct activation verbalizer" baseline: (activations of current window) → answer about future completion. Our observer must beat it *trained on the same labels* (e.g., QA "Will the response become unsafe? When?" / "What topics will the rest cover?").
- Reusable code: activation capture hooks + placeholder substitution at layer 0; training loop with LoRA. Supports Qwen3-4B-Instruct-2507 and Llama-3-8B-Instruct out of the box (fits 1× A6000 48GB with LoRA for 4B; 8B needs care).
- Gap our hypothesis targets: LIT has no explicit time axis, no multi-scale future latent objective, no memory of a growing trajectory (reads a fixed ~50-token window), and its labels are whole-completion properties. Lead-time-stratified evaluation is absent.

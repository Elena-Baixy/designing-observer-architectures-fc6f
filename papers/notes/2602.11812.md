# 2602.11812 — Predicting LLM Output Length via Entropy-Guided Representations (Xie, Chen, Wang, Hu, Wang; KAUST/MBZUAI; ICLR 2026)

Read depth: DEEP (all 34 pages incl. appendices B–E).

## Research question
Can an LLM's own hidden states (instead of an auxiliary BERT/OPT predictor) predict how long its output will be, both (i) statically from the prompt before decoding and (ii) progressively during stochastic "one-to-many" decoding (e.g., GRPO RL sampling with K samples per prompt)? Motivation: length-aware scheduling to reduce padding ("barrel effect") in batched serving / RL rollouts.

## Method / architecture
1. **EGTP (Entropy-Guided Token Pooling)** — static prediction from prompt activations.
   - Motivation check: gradient attribution I_t = ||∇_{h_t} L_MSE||_2 (BERT + linear head, 10k LMSYS samples) correlates with next-token entropy, Pearson r = 0.451.
   - Per-token entropy H_i = −Σ_v P(v|x_<i) log P(v|x_<i).
   - Weights w_i = exp(H_i)/Σ_j exp(H_j) (text mentions a temperature α but Eq. 3 is written without it).
   - Pooled h = Σ_i w_i h_i.
2. **Length regression via soft label distribution** (the prediction head):
   - Discretize length into K bins; soft target p_j = exp(−|j−i|)/Σ_k exp(−|k−i|) for true bin i.
   - Head outputs softmax p̂ over K bins; regression ŷ = Σ_i p̂_i c_i (c_i = bin centre).
   - Loss L = λ·CE(p, p̂) + (1−λ)·MSE(y, ŷ). K = 20, λ = 0.95 (main); ablation on LMSYS finds λ = 0.99 best (MAE ~68), λ=1 ~70, λ=0 (pure MSE) ~82–84 (MSE scale dominates gradient).
3. **PLP (Progressive Length Prediction)** — at each decoding step t predict remaining tokens y_rem^(t) from z_t = Aggregate(h, {h'_1..h'_t}) where Aggregate = concatenation; same head; loss L_PLP = (1/T) Σ_t L(y_rem^(t), ŷ_rem^(t)).

## Models
Qwen2.5 (0.5B, 1.5B, 3B, 7B; Instruct), Llama3.2 (1B, 3B; Instruct), DeepSeek-R1-Distill (Qwen-1.5B, Qwen-7B, Llama-8B) for reasoning. LMSYS evaluation uses GPT-4 and Claude-2 responses.

## Datasets
- **ForeLen** (released): HF `abinzzz/ForeLen` (https://huggingface.co/datasets/abinzzz/ForeLen). 23,556 unique prompts (train 14,134 / val 4,711 / test 4,711; 3:1:1, follows official splits so test prompts unseen).
  - Long-Sequence (4.7%): LongBench 550, ZeroSCROLLS 550 (prompts mean ~5.9k chars; responses mean 1,172 / 1,420, max 7,106 / 3,626).
  - Reasoning (2.3%): IFEval 550 (response mean 1,586, max 3,730; <think>/<answer> format).
  - RL (93%): GRPO rollouts, K=4 samples/prompt, from CRUXEval 800, GSM8K 7,471, LiveCodeBench 1,055, MATH 7,500, MBPP 1,929, MMLU-STEM 3,151 (response means 594–2,188; maxima 6.4k–8.1k).
  - Length unit in Table 5 is not explicitly stated (described as characters for prompts).
- LMSYS (LMSYS-Chat-1M) for GPT-4/Claude-2 responses.
- OOD super-long: `euclaise/writingprompts` (longest >17k tokens).

## Probe design
- Layer: final transformer layer for all models. Layer ablation (Qwen2.5-0.5B, 24 layers, GSM8K): L1 MAE 85.91, L8 81.29, **L12 70.26 (best MAE)**, L16 70.79, L24 73.93 (best RMSE 92.95). Mid layers ≈ final.
- Pooling: entropy-weighted mean over prompt tokens (vs mean/max/last-token).
- Head: lightweight linear head over K=20 bins (5–7 MB VRAM, ~0.66 ms/query).
- Training: AdamW lr 2e-5, ≤10 epochs, batch 16, seed 42, 1 V100.

## Metrics
MAE (main), RMSE (some ablations); system: throughput, avg Job Completion Time (JCT), padding ratio. No calibration or distributional metrics despite having a predicted distribution p̂.

## Limitations (observed)
- Target is a single scalar (length) — no semantic/content attributes, no event timing beyond EOS.
- PLP evaluated only to 32 decoding steps; no analysis of how error varies with the actual remaining horizon (e.g. stratified by true remaining length).
- Aggregate() is "simple concatenation" — unclear how variable-length concatenation feeds a fixed head; no memory/recurrent model.
- No calibration / interval metrics; no seeds/CIs for main table (single seed 42), std only in appendix ablations.
- Section E.4 "Analysis of prediction stability" heading is present with no content.
- ForeLen is 93% RL math/code data; long-form open-ended generation is a small share (1,100 Long-Seq prompts).

## Relevance to observer/forecasting hypothesis
- **Direct baseline for "time-to-EOS" forecasting**: EOS time is a natural, label-free event-time target. A discrete-time hazard head over remaining-length bins is a strict generalization of their soft-label K-bin head; the observer could be compared directly against EGTP/PLP (last-layer, linear head) on ForeLen with MAE plus survival metrics (C-index, IBS) they omit.
- **Loss design lessons**: binned distribution + distance-aware soft labels + small expected-value MSE term beat log-regression and pure MSE on heavy-tailed lengths. For a hazard head, analogous: discretize horizon into bins (log-spaced), use NLL with censoring, optionally add an expected-time regression term with tiny weight (λ≈0.95–0.99 on the distributional term).
- **Pooling/memory**: entropy-weighted pooling >> mean pooling (155 → 103 MAE) and >> last token; supports the hypothesis that a single-position probe (last token, AO-style) underuses trajectory information. The observer's memory could use entropy as an attention prior / extra input feature.
- **Horizon/position evidence**: PLP shows remaining-length prediction improves as more trajectory is observed, i.e. trajectory history helps; but they never test long lead distances. Testing gain vs. remaining horizon (100–2048 tokens) on ForeLen would be a clean experiment.
- **Layer choice**: middle layer (L12/24) ≈ final; sweep mid-to-late layers.
- **Dataset**: ForeLen gives long responses (means 0.6k–2.2k, max ~8k) with exact lengths across 6 models; RL subset has 4 samples/prompt, enabling evaluation of the "one-to-many" stochastic setting (observer must condition on the realized trajectory, not just prompt). No content attribute labels though.

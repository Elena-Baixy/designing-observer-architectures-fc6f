\section{Implementation and reproducibility}
\label{app:impl}

\para{Hardware and time.}
All experiments run on one RTX A6000 (48\,GB) with Python 3.12, PyTorch 2.14 and transformers 5.20.
Generation took 423\,s plus 108\,s, activation caching about one minute, and observer training 2--4\,s per model per seed.
Annotation used 96 LLM calls costing under \$1.
An earlier generation run with 216 prompts ran out of GPU memory and was discarded; the final 96-prompt family split was again fixed before generation.

\para{Annotation rubric.}
For each 64-token segment (\qwen tokenizer), the annotator returns a behavior from \{explain, instruct, recommend, narrate, refuse, warn, other\}, a 1--3 word topic, an unsafe flag and a description of at most 15 words, plus an overall response summary.

\para{Leakage audit.}
Observer inputs are blocks that end at or before the cutoff, asserted in code; future-window activations are used only as JEPA targets; topic clusters and standardization statistics are fit on train only; and the family split is asserted disjoint.

\para{Reproducibility check.}
Re-running \directao and \hq on the unsafe event with seed 0 reproduces \directao exactly (AUROC 0.480 / 0.776 / 0.811 at $H$ = 64 / 512 / 1024) and \hq within seed noise (0.500 / 0.807 / 0.833 vs.\ the original 0.465 / 0.789 / 0.829); the differences come from non-deterministic CUDA attention kernels.
